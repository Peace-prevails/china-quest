# China Quest — Codex 完整项目交接说明（2026-10-27 确定版）

你是该项目的执行开发者。请阅读此文件并将剧情、角色、素材、程序建立为可版本化文件。**不要自行改写故事主线，不要使用旧版“两个未婚夫／求婚”剧本**。目标是先实现「剧本 → 图片清单 → Seedream 图片 API → 本地文件 → 人工审核」的完整自动化流水线；再将素材接入手机端互动剧情游戏。先完成能本地运行、可验收的代码，不要仅提供框架或伪代码。

## 1. 产品定位与核心规则

- 面向海外零基础中文学习者；手机浏览器访问，第一人称、主角不预设性别/外貌。
- 类型：北京都市荒诞悬疑短剧 + 中文学习 + 受限探索（Hub-and-Spoke）。
- 玩家可点击物体热点、查看菜单、与 NPC 进行有限对话；每次从 2–4 个中文台词选项中选择。禁止第一版自由文本输入。
- 用户零基础：首次出现关键中文时提供中文语音、拼音、英文提示；之后允许玩家自主展开提示，不因看不懂而卡死。默认显示明确的任务提示（英文）。
- 语言行动产生剧情后果，不能做单纯正确/错误测验。允许“我听不懂”触发 NPC 简化重说。
- 同一高频句型在不同场景复现；追踪提示使用及语义迁移，但不要把点击行为称为真实口语能力。
- 探索限定在可重玩的固定对象及短对话中；主线在剧情触发时收束，不能指数级分叉。
- 首集建议首次游玩 8–10 分钟；不要求注册；第一集免费。

## 2. 第一季故事核心（初稿，可持续规划但须保留已设伏笔）

第一季背景在北京，玩家是刚到北京的外国游客，本想旅游，却因在胡同面馆点餐而卷入一场诡异的十亿元遗产纠纷。顾承泽带着遗产文件找到玩家，第二名争夺者否认顾承泽的判断；老板娘认出文件上的旧名字并透露此人曾被认为已死。陌生短信约玩家次日中午到文件上的地址。后续需解释遗产、身份错认、旧人死亡传闻与两名争夺者的真实动机；尚未确定的最终谜底，不得伪装为已确定事实。避免强制恋爱线及玩家性别假设。

可能的后续学习场景：EP02 地铁问路（去哪里／怎么走），EP03 商场购物（这个／那个／太贵了），EP04 四合院询问人物（谁／认识），EP05 餐厅交流（喜欢／可以吗），EP06 胡同揭秘（为什么／怎么办）。这是规划方向而非已确认完整剧本。

## 3. 第一集正式标题、教学目标、角色

EP01《一碗牛肉面，十亿遗产》 / The Billion-Yuan Noodles。地点：北京胡同口、虚构“好运面馆”（绝大部分剧情只在此处）。

**教学句型：** 我要……；我不要……；这个／那个；这个是什么？；多少钱？；在哪里？；你是谁？；我不认识你／他；我听不懂。优先保证日常通用性，惊悚故事使用这些句型制造戏剧反差。

**角色（外貌待生成候选后人工锁定）：**
- 老板娘：43 岁左右北京胡同面馆女老板，爽快、精明、生活化。方圆脸、左侧浅法令纹更深、眼尾细纹、略不整齐的眉型、小幅度牙列差异，自然肤色、真实皮肤纹理。常穿深色针织衫及洗旧围裙。
- 小陈：24 岁左右北京男服务员，机灵嘴快，略方偏长脸、单眼皮/内双不完全对称、鼻尖微圆、短乱发、颧部细小痘印；朴素工作服。
- 顾承泽：31 岁男性，富家人、有控制感但压着焦虑，偏瘦长脸、左眉尾轻微断眉、右侧鼻梁不完美、眼周有疲惫纹理、薄唇、常穿黑西装。不能是标准化偶像脸。
- 第二位争夺者（暂名“陆骁”，角色名标记 provisional）：33 岁男性，更急、更直接，宽下颌、眉骨明显、微不对称耳朵、鼻背轻微旧伤、肤质偏粗、深灰风衣。与顾承泽不能长得相像。
- 路人阿姨为开场可选旁白/小角色，可只用环境与文本，不必生成第五张主角色立绘。

角色特征为生成方向，不是保证模型百分之百保留。实际人脸身份通过 `approved_reference_image` 锁定，并用参考图约束后续制作。

## 4. 第一集逐场景互动剧本（唯一真值）

所有台词字段至少有 `zh`、`en`、可选 `pinyin`、speaker、节点 ID、选项、跳转、前置条件、状态更新及语言标签。以下中文仅为首版内容，正式生成时保留语义并检查自然度与语音发音。

### S0 胡同入口：引导 / 找面馆
背景：BG_HUTONG。傍晚玩家拖着行李，手机快没电，想吃饭；远处“好运面馆”灯牌。
任务英文：“Find a noodle shop.”
热点：看招牌（查看“面馆”）、问路人（“面馆在哪里？”→“往前走，右边。”）、直接往前走。问路也可选“我听不懂”→阿姨重说“前面，右边。”
所有路线汇合 S1；状态 `asked_directions`、`used_help_location`。

### S1 面馆内：认识对象
背景：BG_SHOP_MAIN；老板娘出场。
老板娘：“你好！吃点什么？” EN: “Hi! What would you like to eat?”
英文任务：“Look at the menu and order something.”
三个可点击热点：墙上菜单（推荐）、老板娘（“我要……”/“我听不懂”）、柜台矿泉水；打开物品卡不单独生成完整新镜头。
玩家进入 S2 菜单并最终 S3 确认点单。

### S2 菜单热点：有限探索 / 真正的视觉学习
使用 UI 原生绘制清晰文本与价格，**不要依赖图片模型写汉字**。菜单仅四项：牛肉面 ¥28、炸酱面 ¥24、矿泉水 ¥3、可乐 ¥5。价格为虚构面馆内部设定。
点击商品显示图标/实物插图、中文、拼音、英文，并提供：“这个是什么？”（老板娘回答“这是牛肉面。”）/“这个多少钱？”（报价格）/“我要这个。”（选中）/关闭。
允许看多个选项、返回菜单，提交必须选至少一份主食。此处的 `item_selected` 决定下一幕实物上菜，支持牛肉面/炸酱面。玩家可说“我听不懂”，显示帮助。

### S3 点餐确认：受限分支
老板娘：“你要牛肉面？”或“你要炸酱面？”（根据 `item_selected`）。
选项：“对，我要这个。”（确认）/“我不要这个。”（回到菜单）/“我听不懂。”（慢速、简化并给英文提示）。
老板娘：“要不要辣？”玩家：“我要辣。” / “我不要辣。” / “我听不懂。”（NPC 重说）。记录 `spicy`。
老板娘：“还要水吗？”玩家：“我要水。” / “我不要水。”。记录 `wants_water`。
上菜台词：“好嘞，面来了！”；食物/饮料按状态展示。所有合法状态可顺利进入 S4。

### S4 价格与付款前：可选但建议触发一个问价机会
玩家可以：“这个多少钱？”（按订单总价动态呈现，别写死）／“水多少钱？”（3 元）／“先吃面。”。
学习“多少钱”；保留漫画式后文“十个亿 vs 28 元”的反差。S4 结束进入 S5。

### S5 限时自由探索：主线前最后的小游戏区域
仍在 BG_SHOP_MAIN，可使用热点导航切换 BG_COUNTER、BG_DOOR，也可复用单一 BG 并以 UI 热点表现。
只允许 5 个热点，每个 2–3 种动作，最多 2–3 轮短对话，不无限生成：
1) 老板娘：“洗手间在哪里？”→“在后面，左边。”；“这个多少钱？”→菜单价；“这是什么？”→“这是菜单。”
2) 小陈：“你是谁？”→“我是小陈，在这里帮忙。”；“这个好吃吗？”→“好吃！”；“门口那是什么？”→“一辆很贵的车。”
3) 菜单：继续看四项，复现这个/那个/多少钱；此处允许练习但不会改变已完成订单。
4) 角落的红色文件袋：看一眼（可观察封套但看不清名字，设置 `saw_red_envelope=true`）、问小陈“这是什么？”→“我不知道。”、不碰。
5) 门口：看外面、问“谁来了？”→“不知道，刚停了一辆车。”、继续吃面。
关键原则：不要求探索完所有点；点击“继续吃面”直接推进 S6。访问过的热点允许重玩。未探索线索保留在回放中。

### S6 顾承泽出现：剧情由日常升级
背景 BG_DOOR + CH_GU 立绘，关键事件 CG_FILE_SLAM 可选播放。
顾承泽：“终于找到你了！这个，是你的。”把正式文件袋放到桌上。
选项：“这是什么？”→“一份遗产文件。”；“你是谁？”→“我叫顾承泽。”；“我不认识你。”→“我知道，但事情很复杂。”；“我要吃饭。”→老板娘插科打诨；“我听不懂。”→顾承泽简化为“这是你的钱。”。
这些是短分支，均收束 S7。保留 `first_reaction`。

### S7 十亿元：本集核心语言迁移
顾承泽：“这十个亿，是你的。你要不要？” EN: “This one billion yuan is yours. Do you want it?”
选项：
- “我要。”→顾承泽拿出笔：“太好了，请在这里签字。”，`inheritance_response=accept`，**不得真让玩家签署法律文件**。
- “我不要。”→“十个亿都不要？为什么？”，`inheritance_response=reject`。
- “这是什么？”→“这是一份遗产文件，名字是你的。”，`inheritance_response=question`。
- “这是谁的？”→顾承泽迟疑：“现在……是你的。”，`inheritance_response=ownership`。
选择后不管如何都由第二人打断、进入 S8；别把上述选项误判为中文错误。若已见红文件袋，追加一句玩家识别文件袋的特殊台词，作为差异化奖励。

### S8 第二争夺者闯入：态度与跨集状态
第二争夺者冲进店：“等等！不能给他！他认错人了！”（由于玩家没有固定性别，NPC 台词只用“你”；此处“他”指顾承泽）。
玩家选项：“你是谁？”、“我不认识他。”、“我也不认识你。”、“文件给我。”。
分别记录 `trust_alignment=question_second/against_gu/distrust_both/wants_document`；每个 NPC 给一句不同反馈但汇合 S9。
注意避免视角歧义，旁白明确“第二个男人指着顾承泽”。

### S9 悬念结尾
老板娘看到文件上某个名字，喃喃：“这个名字……我二十年前见过。”“不可能，那个人不是已经死了吗？”
玩家任选：“什么意思？”、“谁死了？”、“这是什么？”；老板娘只说：“现在不能说。”
手机屏幕收到简体中文短信（UI 文本渲染，不依赖生成图写字）：“不要相信他们。明天中午，去文件上的地址。” 翻译英文可点开。
画面黑，EP01 END。记录完整 `episode_01_state` 留给 EP02；玩家可以回放探索，不要求重新看所有剧情。

## 5. 数据约束和状态机规范

建议结构：`season_bible.json`, `character_bible.json`, `episode_01.json`, `asset_manifest.json`, `style_guide.md`。节点 schema 应包含 `id`,`scene_id`,`speaker`,`zh`,`en`,`pinyin`,`asset_refs`,`learning_tags`,`choices:[{id,zh,en,pinyin,next,set,requires}]` 与必要的控制型节点。首次生成时检查所有 `next` 存在、所有必经路径可达终点、无限循环受控、没有死节点和不可达内容；剧情控制状态与学习记录分离。第一集在 S5 允许回访 NPC，但在主线推进后关闭热点，避免状态冲突。

状态：`item_selected`, `spicy`, `wants_water`, `asked_directions`, `explored_hotspots[]`, `saw_red_envelope`, `first_reaction`, `inheritance_response`, `trust_alignment`, `hint_usage`, `phrase_exposure`, `replay_count`。不要自动把“点击正确”解释为掌握了口语。

## 7. 美术规范与一致性

摄影级真实效果，近似真实摄影机拍出的北京现实主义都市短剧剧照。自然室内混合光、可信的老胡同灰砖、北方小店磨损痕迹、真实物品尺度，允许现实中的小瑕疵。NPC 必须各具面部辨识点：自然毛孔、浅痘印、不对称眉毛、眼周细纹、不过度统一的鼻嘴结构；禁止蜡像/塑料磨皮/通用网红模板脸、锐化过度、过度电影滤镜、假中文字及不合理手指。关键 Prompt 不只写 'realistic'，需结合角色独特特征与真实摄影灯光、镜头距离、装束以及场景布局。

采用两阶段：
1. 每名角色先生成 3 张候选，人工选定 `approved_reference_image`；核心 BG02 生成 2–3 张并锁定布局。候选数量需明确预算。
2. 后续所有人物及同一空间镜头必须引用已批准标准参考图，采用 Seedream 官方支持的图生图 / 多图参考能力，提示词和生成记录可追溯。角色参考图、场景参考图的路径保持不可变并记录版本。API 参考图并非 100% 锁脸：严审不合格图，必要时局部编辑，不要在无人审核条件下连锁生成几十张。

**模型策略：** 草稿默认选择支持的 Seedream flash（以实际控制台可用模型 ID 和当期价格为准），关键角色定稿/关键 CG 采用 pro。先查官方文档、以用户控制台可用真实模型标识调用，不能臆造 `model` 名字、价格或返回字段。若 pro/flash 价格关系与预期不同，可调整选择。程序应允许每类资产指定模型、解析度、预算上限和参考图数组。

## 8. 自动化流水线技术要求

使用 Python 3.11+、火山方舟 Seedream 官方图片 API。读取本地 `.env` 中 `ARK_API_KEY`，绝不要求在聊天发送 Key；把 `.env` 加入 `.gitignore`。接口参数、结果结构参照官方最新文档 `https://console.volcengine.com/ark/region:cn-beijing/docs/image-generation-api`。真实调用前先 dry-run；一次测试只生成一张；网络错误重试需指数退避，避免重复扣费；图片立即下载到本地，保存响应元数据和 SHA256；支持部分失败、断点续跑、同 prompt/参考图缓存去重；所有任务可审计。

文件组织建议：
```
china-quest/
  data/season_bible.json
  data/character_bible.json
  episodes/ep01/episode_01.json
  episodes/ep01/asset_manifest.json
  docs/style_guide.md
  assets/generated/{characters,backgrounds,props,cg}/
  assets/approved/{characters,backgrounds,props,cg}/
  scripts/generate_assets.py
  scripts/review_assets.py
  scripts/validate_story.py
  .env.example
  .gitignore
  README.md
```

CLI 至少支持 `--dry-run`, `--asset-id`, `--max-images`, `--max-spend-rmb`（若无官方单次价格资料，不自动估算；明确提示手动确认）, `--model`, `--resume`；审批要求 generated → approved/rejected，只有 approved 可作为后续参考图。软件不能在没有用户批准费用和批次数量时自动大量调用付费 API。使用本地文件或简易 HTML 画廊审核候选图均可。

第一步按优先顺序：创建项目和完整数据文件 → schema/剧情连通性检查 → 实现 1 张图片的 dry-run 与真实调用下载 → 审核流程 → 角色参考图候选生成 → 锁背景 → 扩展其余素材。每步需有可运行验收命令与 README。未来配音/视频另外建 adapter，本阶段不充值或调用。

## 9. 不可忽略的细节

- 中文菜单、手机短信、价格等用前端文字渲染，避免模型中文字乱码。
- 普通话教学标准音与 NPC 北京口音将来作为两条独立音轨；本阶段先保留 `voice_style` 结构，不做 TTS。
